Light-DOM slots

<slot> without a shadow root. The same template distributes content in light DOM and in shadow DOM, so a component is written once and the consumer picks the mode — and in light DOM the distributed nodes stay ordinary page nodes, reachable by ordinary CSS and ordinary querySelector.

Everything here runs in the browser with no toolchain. View source: the whole demo is one inline module at the bottom of this file.

1 — the wiring, which is the whole setup

import { wire } from '@verajs/core';
import { renderer } from '@verajs/renderer';
import { slots } from '@verajs/renderer/slots';

wire([renderer, slots]);

Wire it at the app entry, before anything renders. A template resolves this once, at construction, and is interned for the life of the page — so a component that rendered before the wiring keeps a slotless template forever. In development the renderer says so, once per tag; these are production bundles, where that check is folded away.

4 — the thing shadow DOM cannot do

A component's stylesheet can reach inside slotted content in light mode. ::slotted() matches only the top-level assigned node, so ::slotted(*) em selects nothing and there is no shadow spelling that works — the nested <em> below is styled by the card's own sheet on the left, and cannot be on the right.

6 — a real component: <vera-select light>

@verajs/ui's select declares four slots. In light mode they are inert unless this page wires the module — which it does, so the slotted trigger below is captured, positioned and wired with the same ARIA and handlers the built-in one gets. The ui-select example is the same component without the wiring, which is why its light section slots nothing.
