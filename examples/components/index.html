Field

gzip …

Wires a form control the consumer writes to its label, hint, count and errors, and renders nothing itself. The control is the [data-vera-part="control"] element, else the first labelable one; the <label> is pointed at it, the hint and count describe it, and the error that shows is chosen from the control's ValidityState once the user has tried (an edit and a blur, or a submit). A user's failed submit focuses the first invalid control in tree order, as native does, and the field cancels native bubbles unless native-messages is set. An error the server rendered (data-when="server") stands until the first edit. The count speaks once per crossing, in the consumer's words and the language's plural form.

Try it Label, hint and errors around your own control. An error appears only after you've tried (submit, or leave the field), never on first sight. Try leaving the email empty, then typing a bad address.

Icon

gzip …

An icon: the consumer's own child <svg>, kept byte-identical, or a src rendered as <svg><use href>. Decorative by default (the host gets aria-hidden="true"); with a label the host gets role="img" and aria-label instead. Only a relative src, or http(s) on the page's own origin, is rendered. Size, color and the RTL flip come from the styles layer, by CSS alone.

Try it Your own SVG, kept exactly as written, or a sprite reference. Decorative by default; a label makes it meaningful to a screen reader. Size and color follow the text.

Input

gzip …

Wraps the user's own <input> (the form participant: autofill, validity, reset and disabled stay the platform's), with optional prefix and suffix parts of the user's. With no <input> inside it renders one, server-side too, from its name, type, value, placeholder and autocomplete, read once. Options add a clear button that keeps the input's undo history, a password reveal, a caps-lock hint (shown and announced), and a loading mark with aria-busy on the input. It never labels: put it in a <label> or a <vera-field>.

Try it The box is ours: the shared border, radius, surface and focus tokens, with your input borderless inside it and the parts beside it. Try clearing (and undoing with Ctrl/Cmd+Z), revealing the password, Escape on the search, and holding a step button on the number.

Reached by doing stepper (wire @vera-components/input/stepper (wire([stepper])), then serve a number input); step-down (wire @vera-components/input/stepper, then serve a number input); step-up (wire @vera-components/input/stepper, then serve a number input).

Tabs

gzip …

Tabs over the author's own buttons and panels: a direct child marked slot="tabs" holds the buttons, the host's other children are the panels. Before the script runs they are buttons and sections; after it, the roles, ids and aria wiring are set, the arrow keys move one tab stop, one panel shows, and an indicator under the selected tab follows it by CSS anchor positioning. A user's selection fires a cancelable beforetabchange, then tabchange.

Try it Judge the behavior: click a tab, move with the arrow keys and Home/End, watch the indicator slide, and use find-in-page (Ctrl+F) for "warranty". Does the indicator keep up with a tab that changes size?
